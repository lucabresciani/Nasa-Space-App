# ✋ WS18 brief — Direct manipulation

> ✂️ **Backend demo cut (D69, Sat 21:16).** Tasks 4–7 need backend features that were cut (user science points, route editing, accounts) and are dropped. Tasks 1–3 stay: live mode (task 3) uses the custom-pad preview and plan job, which are kept.

> 📌 **Goal.** Let users plan by touching the terrain and see at once what a change costs in getting home. Flagship: **drag the rover**. **Feature:** U15 (Tier A: drag the rover, undo; Tier B: science points, ghost route, insert, reorder). **Reviewers:** D (interaction), N (backend calls).

## Owns

`web/src/edit/` (plan-edit store, gestures, ghost and delta strip, undo/redo).

## Reads

The selection and mission stores (WS15), `fieldAt` and the ghost-route layer (WS16), `pads/index.json`, the live API client (WS13: preview, jobs), `config/design.yaml` (`edit:`, `pad_validity:`).

## The honesty rule

While dragging, show only values that are exact from fields already in the browser (time home and margin at the cell, slope, cell state, access cell). Everything else is a ghost marked "computing…" and computed on release. Never an estimated route length during a drag.

## Tasks in order

1. **Plan-edit store (V2):** draft inputs, ghost result, delta, undo stack (50 steps), keyboard Ctrl+Z / Ctrl+Shift+Z, buttons; plan hash per step.
2. **Drag the rover, static mode (V2):** snap between the precomputed parking options; cross-fade their homelines; card updates.
3. **Drag the rover, live mode (V2 if backend B1 is green):** live validity from fields (assessed, ≤ 5° over 20 × 20 m, flat disc inside the grid); preview endpoint at most 2 requests per second (feasible EVAs, reachable stations); release starts the full plan job with the stepper; homeline cross-fades.
4. **Science points (Tier B, needs backend):** drop and drag with exact live values; snap to the nearest access cell within 50 m with the offset shown; on release the ghost route and the delta strip ("+14 min EVA · +11 L O₂ · tightest margin 41 → 29 min (dose)"); Keep or Escape.
5. **Insert on a leg (Tier B):** same as a science point, placed on the selected leg.
6. **Reorder stations (Tier B):** drag in the list or on the map; ghost order; route with fixed order; infeasible legs in red with the binding limit.
7. **Save with versions** when logged in (F27).

## Acceptance tests (write first)

- Live time home during a drag equals the field value at that cell.
- Never more than 2 requests per second during a drag.
- Undo restores the exact previous plan hash; redo returns.
- Static mode never offers an option that needs the server; the card says why.
- An infeasible reorder reports the right leg and limit.

## Don't

Compute routes in the browser; show unlabelled estimates; block the map while a job runs.

## Fallback

Backend not ready: ship static drag-the-rover (snap) and undo only.
