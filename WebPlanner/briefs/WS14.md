## Rules specific to this workstream

1. **The planner's frame and formats are fixed** (east, north, up in metres from the pad; JSON; float32 little-endian grids, row 0 = north). No Unity-specific exports.
2. **The bundle is built from a result tree**, never from separate computations.
3. **The simulator runs locally from the bundle.** Sessions are an add-on; nothing may require the server per frame.
4. **`docs/simulator.md` for a reader who has never seen this repo:** file list, units, frame conversion, sampling rule, the golden test, example requests.
5. **Open frame issue (risk A7):** the world pack is in the official pad's frame; a custom-pad plan bundle is in its own pad frame. Propose to C how the world index states the projected origin before B2′.

## Known-answer tests

- The bundle validates; the frame transform round-trips under 1 cm; the official hash's bundle equals the fixture.
- The reference implementation reproduces every golden vector.
- A float32 field read back equals the result tree's field exactly.
- A replay of the planned route gives margins within ±0.5 min of the timeline and alarms at the planned times.
- A wrong or missing write key is refused; a reconnect continues the session.
