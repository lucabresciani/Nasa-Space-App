## Owns

`web/src/live/` and its tests. Changes to shared web code (a mount slot, a route) go through WS5 or C by a small PR. The loader base URL is already in place: `dataUrl(path, mode, base)` and `browserFetcher(mode, base)` (P0).

## Rules specific to this workstream

1. **Static first.** All live code is lazy-loaded. If `/health` does not answer in 2 s (`config/backend.yaml api.health_timeout_s`), live controls are replaced by "Live planning is offline · showing precomputed plans". No static view imports from `web/src/live/`.
2. **One rendering path.** A live result is loaded as a data tree through the existing contract-checking loader (`createLoader(browserFetcher('real', base), 'real')`). No second renderer.
3. **Label everything live:** "Computed live · not part of the validated scorecard" and a link to the provenance view. The official pad's headline never changes.
4. **Numbers through the manifest.** Live numbers use the result's own `manifest.json` with the existing number component.
5. **Start on mocks.** Until B1′, develop against recorded responses generated from `contracts/` (backend family) (same idea as the dummy data).
6. **D54:** WS18 (design block) later builds on this client; keep its API small and documented.
