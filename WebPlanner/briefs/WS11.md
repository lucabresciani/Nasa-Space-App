## Rules specific to this workstream

1. **No second engine.** Every number comes from calling `pipeline/engine` (`build_plan`, `station_fields`, WS2 branch `ws2-backend-support`).
2. **Results are data trees.** A job writes `results/{hash}/` with the same file names and schemas as `web/public/data/`, plus `run_record.json`, and validates it before reporting success.
3. **Parity first (D56).** The first real endpoint is "official pad, default inputs"; it must equal the precomputed tree before anything else is built on it. CI: synthetic world. Real data: `make parity` before every merge touching `server/engine`.
4. **Hash (D57)** exactly as `contracts/README.md ("Backend family")`.
5. **Every constant from config** (`config/backend.yaml`, read through `server/settings.py`).
6. **Core has priority.** If a core re-run needs the machine, the server data build waits.

## Known-answer tests

- Official pad and default inputs equal the precomputed tree (fields exact, GeoJSON to 6 decimals, manifest values equal).
- Preview route time equals the full plan within 1%.
- Invalid pad reasons: slope, unknown terrain, disc off the grid.
- Heavier suit never increases the reachable area; defaults reproduce the precomputed scenario.
- Same inputs give one hash and one job; a changed engine tree gives a new hash; a title change does not.
- A timed-out job frees its worker and reports an error.
